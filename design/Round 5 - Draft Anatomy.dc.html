Round 5 · the draft's anatomy

Four things the shipped draft doesn't say out loud

All four share a shape: the draft knows something it isn't telling. It knows the map is optional furniture, it knows an address and a person are one fact, it knows which parcels touch which door — and it knows the row, the callout and the item are asking that last question in three different vocabularies. Each answer below makes an existing truth visible rather than adding a feature.

Ids continue the series: 7a map optional · 7b one point, one screen · 7c parcel actions per point · 7d one component, three places. Copy is Russian-first from English source strings.

7a

The map becomes optional

Decision · a DisclosureGroup, plus a Settings switch

The map is the first row of the route card's Form, wrapped in a DisclosureGroup whose content is the map and whose label is «Карта» with a route micro-preview. Precedent is already native: the inline .graphical date picker in Calendar and Reminders is exactly this — a heavy view living inside a disclosed form row. It brings the chevron, the rotation, the expand animation, and the expanded/collapsed accessibility trait for free.

The Settings switch stays, because the two answer different questions: the disclosure is «not right now», the switch is «not ever». isExpanded binds to draft state seeded from the preference — per-session collapse, permanent default.

Rejected: a custom row with a «Показать» text button — a hand-rolled disclosure that has to re-earn its accessibility. Rejected: Settings-only (too far from the moment of need). Rejected: collapse-only (a standing preference becomes a daily chore).

KEPT VARIANT Full-bleed map, floating collapse

The map above the card, edge to edge, with a floating «Свернуть» pill on it — what this board drew before the disclosure. Not deleted, because it is genuinely better at one thing: a full-width map is a better map, and an inset one inside a form row reads as a picture of a map. If the draft ever becomes map-led again, this is the shape to return to.

Why it is not current: a floating pill is a custom control that must re-earn its expanded/collapsed accessibility, and the collapsed state has nowhere native to live — it becomes a bespoke row anyway. Revisit if regular width (6c) makes the map a permanent side pane, where full-bleed costs nothing and no disclosure is needed at all.

Decision · the estimate bar moves to the card, always

It becomes the route card's first row, in both states. The estimate describes the route, and the route card is the route — on the map it was an overlay on the thing it described; on the card it is a header on the thing it describes. Its height and its failure state are unchanged.

Rejected: keeping it on the map inset when the map is shown. One element with two homes means a collapse that migrates content between containers, and a conditional layout to maintain for no gain.

Decision · collapsed is the default at accessibility sizes

The map becomes the first rung of the 3f (folded into DesignSystem.md) ladder — dropped before any content is sacrificed. It is the only element on the screen whose removal costs no information, because the rows are already its legend. Starving type to keep decoration would be the wrong trade.

Auto-collapse is stated, not silent: one dismissible line the first time, with «Показать». Never a silent removal — that reads as a missing feature.

7b

A point is one screen

Two sheets exist because the app thinks an address and a person are two facts. They are one: a door, and who opens it. The unified screen is one sheet with two states — find and describe — where the fast path never reaches the second. Choosing a remembered point that carries its person is done: sheet dismissed, row complete, no contact step. Only a raw address needs describing.

Decision · one sheet, two states, in-place transition

Find replaces itself with Describe inside the same sheet — not a push, not a second sheet. The header's back arrow returns to Find; Отмена always abandons the whole point. One dismissal gesture means one mental model.

Rejected: a navigation push (two back affordances, and the sheet's height would jump twice). Rejected: one long scroll containing both (search results and address parts competing for the same keyboard).

Decision · «Ещё точка» opens the sheet, never a blank row

The row appears only when the sheet completes, with its role pre-set by position. A blank row is a promise the draft can't keep — it is also the direct cause of the useless stop in 7c, so the fix belongs here as much as there.

Rejected: today's drop-and-walk-away. Rejected: a row that self-deletes on dismiss — silent deletion is worse than never appearing.

Decision · «никого не будет» is data, not an empty field

A постамат has no person, and a point must be able to remember that. An explicit state stops the app nagging forever about a contact that will never exist, and lets a remembered point speak for its own door even when nobody is behind it.

Rejected: treating empty as unknown (permanent warning on a correct point). Where the API demands a contact, the sentence names that — and the field stays required.

7c

Every point states its parcel actions

The route and the parcels are one fact seen from two ends, and today each end is silent about the other. Point rows gain a parcel-action line; item rows gain a journey line; and silent repair marks itself on both. The vocabulary is deliberately not new badge shapes — 2c (folded into DesignSystem.md) badges say which stop this is, and a second shape system competing with them would make both harder to read.

Decision · the point row is a DisclosureGroup too

Collapsed label carries the counted sentence — «Забирает 2 · отдаёт 1» — and expanding lists exactly which items, each tappable through to the item. The route list is already a Form, the relationship is genuinely hierarchical, and the count is a faithful summary of the content beneath it, which is the test for a disclosure rather than a link.

Rejected: a chevron pushing to a per-point item screen (a whole screen to say «one box»). Watch: rows are drag-reorderable; collapse on drag begin, and never allow reordering from inside an expanded row.

Decision · words first, glyphs second

«Забирает 2 · отдаёт 1», with shippingbox.fill and house.fill ahead of each count — the same pair 2c (folded into DesignSystem.md) already assigns to those actions, so nothing new is invented. Zero is stated, not omitted: «Ничего не забирает и не отдаёт» is the whole point of the line.

Rejected: icon-plus-number with no words (unreadable at a glance and untranslatable to speech). Rejected: colour-coding the counts — status colour is spoken for, and counts are not statuses.

Decision · a useless stop blocks, in a sentence

The house blocks with sentences, so: «На Тверской, 6 курьер ничего не заберёт и не отдаст. Уберите точку или отправьте что-нибудь через неё.» Both remedies are offered inline. A stop nobody uses is not a warning — it is a route the sender did not mean to build, and it costs money and time in the real world.

Rejected: a soft warning that lets it through to review. Rejected: auto-removal — silent deletion of something the sender typed is never acceptable.

Decision · repair announces itself once, on both sides

When a route edit silently re-points an item's journey, the item row's journey line marks the changed end and the affected point rows show «маршрут вещи изменён» until the draft is next opened. This is the design half of TechDebt YD-6: the repair is correct, its invisibility is the bug.

Rejected: an alert per repair (deleting a stop with four items would fire four times). Rejected: staying silent, which is today.

7d

One component, three places

«Что здесь происходит с посылками» is one answer, so it must be one view — and today it would be three: the disclosure from 7c, the callout in 4a, and an inline picker in 3d (folded into DesignSystem.md) that invented a third vocabulary. Two rules settle it. The parcel-action block is a single view reused verbatim by the row and the callout. The item's path is exactly two rows, and those rows are route point rows — same badge, same two-line shape, same tap behaviour.

Decision · PointParcelActions is one view, two hosts

The counted sentence plus the grouped item list, rendered identically inside the row's DisclosureGroup and inside the map callout. It joins the shared set in 5e, so a change to the vocabulary lands in both places or neither.

Rejected: a compact callout variant with its own shorter phrasing. Two phrasings for one fact is how «отдаёт 2» and «2 вещи» end up on the same screen meaning the same thing.

Decision · selection is symmetric

Tapping a pin opens the callout and expands + scrolls to its row. Tapping a row expands it and opens the callout, centring the pin. One selected point at a time, one state driving both — the map is a second view of the list, not a second app.

Rejected: pin→callout only (4a as drawn), which made the map a dead end the list could not reach. Note: map hidden per 7a — row expansion is simply the whole behaviour, and nothing is lost.

Decision · the item's path is two point rows, never a picker

You are right that the inline picker was nonsense: it asked about places while looking nothing like the places. «Путь вещи» is two rows — pick up, hand over — each drawn as a route point row with its 2c (folded into DesignSystem.md) badge, address and role line. Tapping one opens the point chooser, itself a list of the same rows.

Rejected: the trailing-value dropdown, and the letters it carried. Hard cap: two rows. An item is picked up once and handed over once; anything else is two items, and the API models it that way too.
